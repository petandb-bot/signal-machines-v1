# Phase 8 prototype — PRINT / A machine remembering itself

**Based on the v0.25 integrity release. Not released.**

SIGNAL MACHINES already produces distinctive, unstable, self-modulating musical material. The new feature should not impose a global song grid, melody system or polish. Instead it allows a running circuit to remember a fragment of its own behaviour, as playable audio.

## First slice — one-bar master PRINT

A **PRINT** button is added to the existing LOOP module. It captures **the full stereo master output** at its audible post-saturation level, without passing through file download/upload or browser MediaRecorder.

- Length: exactly 4 beats at the current BPM, beginning **after a short ~8 ms transition** from the destination LOOP's prior playback; not snapped to a global downbeat. At 20–300 BPM this is 12–0.8 seconds, within the existing 16s LOOP memory.
- Captured material: the audible master after the current gain and the existing soft ceiling; not the direct LOOP input. Other generators, FX, chance, timing and other LOOP layers are preserved in the captured sound.
- To prevent direct recapture, **the destination LOOP's previous playback is muted during PRINT**. Its live input still passes through while printing, so existing paths through the module remain audible.
- At the end of one bar, the destination LOOP automatically enters **Playing**; the existing SPEED and MIX controls immediately turn the printed memory into a playable layer. Negative speed, frozen motion and repeated tempo changes remain legitimate.
- PRINT can be canceled by **Clear**; transport stop finalizes a partial take. A second PRINT is rejected while one is already running.
- For best results route a generator to OUTPUT and route LOOP AUDIO to OUTPUT or an intermediate module to listen to its captured material. No automatic cabling, hidden pattern generators or new DSP modules.

## Intentional artistic properties

- The player controls *when* the instrument remembers something. The feature does not quantize event onset to a common metronome.
- Previous signals can remain in downstream filters and reverbs; these audible tails are part of the master and intentionally remain in the printed memory. Direct old LOOP playback and its short transition are excluded from the new capture.
- A captured fragment may have material discontinuities inside it; they are kept. The existing LOOP edge window and short transition handle the playback boundary.
- LOOP is a memory and transformation stage, not an automatic mastering effect.
- Source sound and past presets remain untouched.

## System constraints

- Reuses LOOP's two existing sliders, PCM arrays and playback/overdub code.
- Sample-by-sample master capture stays in the AudioWorklet; does not post the PCM block to the UI or allocate in per-sample loops.
- One active PRINT job per graph. Explicitly disallow parallel target capture.
- Stored patch JSON is unchanged, and still contains no audio samples. Saving or recalling a patch does not serialize printed memory. Use Export WAV if a take must survive recall.
- Existing WAV/AIFF master recordings and LOOP input Record/Dub remain fully independent.
- Running iPhone Safari must be tested on device; CI runs do not prove real-time mobile performance.

## Minimum acceptance

- Printed stereo buffer equals a reference render of the **actual post-master PCM**, at 8/44.1/48 kHz.
- The destination LOOP's old playback and its 8ms fade are not reprinted into itself.
- Cancellation, removal of destination module, STOP/RUN and changing routes do not leave stale capture state.
- No samples outside the 16s buffer, no overruns, no non-finite outputs.
- Existing v0.25 DSP compatibility and 20 presets remain unchanged.
- Mode display and buttons remain comprehensible on phone and desktop.

## Possible next explorations, not in this PR

1. Return a printed fragment to a different module without an external file.
2. Non-uniform memory durations generated by the machine itself, rather than conventional bars.
3. Cooperative memory between two LOOP modules with independent time drift.

These should follow listening evaluation, not be bundled into the first prototype.
